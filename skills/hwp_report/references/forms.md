# 다른 양식 쓰기

기본 양식은 2026 전략연구사업 연차점검 보고서(양식1)다(`assets/forms/annual_review_2026/`).
다른 양식을 쓰려면 등록하고, 등록하면 그 양식이 기본이 된다.

```bash
HR config add-form 새양식.hwpx --name 단계보고서_2027   # ~/.hwp_report/forms/단계보고서_2027/ 에 복사 + 분석 + 프로필 초안
HR config forms                                         # 등록된 양식 목록(* = 지금 기본)
HR config set form default                              # 기본 양식으로 되돌리기
```

- `.hwp`는 한글에서 「다른 이름으로 저장 → hwpx」로 바꿔서 받는다.
- spec에 `form: <이름>`을 적으면 그 보고서만 다른 양식으로 만든다.

## 등록하면 생기는 것

`add-form`은 양식을 분석해 네 가지를 보여 준다.
1. 기본 양식의 제목(정규식) 가운데 이 양식에 있는 것과 없는 것
2. 제목 후보 목록
3. 표 목록(크기, 바로 앞 제목)
4. 예시·자리표시 문단

그리고 `profile.yaml` 초안을 만든다.
- 찾은 제목은 그대로 두고, 못 찾은 제목은 `null`로 둔다. 엔진은 null인 절을 건너뛴다.
- `suggested_sections`: 이 양식의 제목 후보다. 절의 끝(경계)을 정할 때도 쓴다.

## 경우별 처리

| 양식 | 할 일 |
|---|---|
| **같은 계열**(다음 해 연차점검, 문구가 조금 바뀐 판) | 분석 결과 ✓가 대부분이면 끝. ✗인 제목은 `profile.yaml`의 정규식을 새 문구에 맞게 고친다 |
| **비슷한 계열**(단계·최종보고서 등 장 구성이 일부 같음) | 맞는 절은 기존 키(overview, work, progress …)로 채운다. 나머지 제목은 spec `sections:`로 채운다 |
| **전혀 다른 양식**(내부 보고서, 기획서 등) | 기존 키는 쓰지 않는다. `sections:`와 `tables:`만 쓴다 |

## spec 예시 — 다른 양식

```yaml
form: 단계보고서_2027
sections:                                # 제목 정규식 → 그 아래 글(다음 제목이나 표 앞까지)을 이 내용으로 바꿈
  '^□ 추진 방향': |
    o 부서별 역할을 데이터 기반으로 재정의
    - …
  '^1\. 연구개발 목표':
    mode: insert                         # 양식 글은 두고 제목 바로 뒤에 덧붙이기(역추출 왕복은 안 됨)
    text: |
      o …
tables:
  - after: '^□ 세부 계획\(안\)'          # 이 제목 뒤 첫 표
    cells: {"1,1": 값}                   # 칸 주소: HR analyze 양식.hwpx 의 표 목록 + references/form_map.md 방식
  - after: '^3\. 추진 일정'
    rows: [[항목, 1분기, 2분기]]           # 머리행 아래 행을 복제해 채움(header_rows 기본 1)
```

## 주의

- 제목 정규식은 문단 앞뒤 공백을 뺀 글자와 비교한다. 같은 제목이 목차에도 있으면 **마지막** 것(본문)을 쓴다.
- `sections:`의 기본 동작(replace)은 제목 아래 양식 글(안내문·예시)을 지운다. 지우면 안 되는 안내문이 있으면 `mode: insert`를 쓴다.
- 표 칸 주소는 `HR analyze`의 표 목록에서 행·열을 센다. 병합 칸은 시작 칸 주소를 쓴다.
- 만든 뒤에는 반드시 `HR check` → `HR render` → 한컴에서 열어 보기 순서로 확인한다. 낯선 양식은 표 행 높이와 쪽 나눔이 어긋날 수 있다.
