# 쪽 배치·그림·검수

## 그림 넣기 (엔진 규약)

- **크기**: 그림은 400 dpi로 설계한 크기 그대로 넣는다(픽셀 × 7200/dpi HWPUNIT, 400 dpi면 × 18). 그래서 그림 안 글자가 설계한 pt 그대로 나온다.
  - 상한은 150 × 105 mm다(`figure_box_mm`). 본문 폭 170 mm를 꽉 채우지 않는다.
  - 상한을 넘는 그림은 비율을 지켜 줄인다. `[그림 ID 폭=110]`으로 폭을 고정할 수 있다.
- **imgDim·imgClip은 원본 픽셀 × 75**(96 dpi 기준 HWPUNIT)로 둔다. 표시 크기를 넣으면 rhwp에서 그림 왼쪽 위만 확대돼 보인다.
- **그림 문단만 줄간격 100%**로 둔다. 160%면 그림 높이 × 1.6으로 잡혀 다음 쪽으로 밀린다.
- **BinData 이름은 한컴 규약대로 `image1`, `image2` …**로 쓴다. 다른 이름이면 rhwp가 그림을 못 찾아 회색 상자로 그린다. spec의 그림 ID(파일 이름)는 바꾸지 않아도 된다. 엔진이 알아서 붙인다.
- 그림 문단은 다음 문단(캡션)과 함께 두고(keepWithNext), 캡션은 가운데 정렬에 위아래 간격 400을 둔다.

## 표 행 높이

- 한컴은 셀 높이를 최소값으로 보고 글이 넘치면 늘린다. rhwp는 늘리지 않아 글이 겹쳐 보인다.
- 그래서 엔진이 글자량으로 행 높이를 추정해 넣는다(`fit_rows`).
- 요약표는 한 쪽에 들어가야 하므로 `summary_fit_rows`에 적은 행만 늘린다.

## 검수 순서

1. **게이트**: `check_report.py report.hwpx --spec report.yaml`
   - 구조(zip·mimetype·XML·스타일 참조·그림 파일)와 작성 규칙(lint)을 본다.
   - ERROR가 0이어야 넘긴다. WARN은 하나씩 읽고 판단한다.
2. **빠른 미리보기**: `bash render.sh report.hwpx` → `report_render/pair_*.png`를 직접 연다.
   - rhwp 헤드리스 렌더라 한컴이 없어도 된다.
   - ⚠️ 줄배치 캐시가 없는 빌드본에서는 큰 그림이 쪽 경계에 걸리면 **뒤 내용을 통째로 빠뜨린다.** 쪽 수가 한컴보다 적게 나온다. 쪽 나눔 판단에는 쓰지 않는다.
3. **최종 쪽 배치**: 한컴 PDF로 확인한다.
   - macOS: `HR pdf report.hwpx` — 원본이 아니라 `HRQA_…` 사본을 열어 PDF만 뽑고 그 창만 닫는다. 작성자가 같은 문서를 열어 두고 있어도 된다.
   - Windows·한컴이 손에 있으면 직접 열어 PDF로 저장한다.
   - 한컴이 열면서 경고(「손상된 문서」, 「복구」)를 띄우지 않는지도 함께 본다.
4. **꼬리 줄**: `HR tail report.pdf --hwpx report.hwpx` — 마지막 줄에 몇 글자(기본 4자 이하)만 넘어간 문단을 찾는다.
   - 한컴은 한글을 **글자 단위로** 줄바꿈한다(「…자동화 측정 / 함」). 미리보기 렌더(rhwp)·LibreOffice의 줄바꿈은 달라서 확정에 쓰지 않는다.
   - 통합 양식이면 `--skip-form 주관기관양식.hwpx`로 남의 글을 빼고 우리 문단만 본다.
   - 고친 뒤 다시 PDF → tail. 한 번 고치면 다른 문단이 밀려 새 꼬리 줄이 생기기도 한다. 0개가 될 때까지 돈다.
   - 어림(실제 한컴 PDF 두 건에서 잰 값): 본문 11~12 pt `-` 문단의 한 줄은 공백을 빼고 약 38~40자다. 숫자·영문이 많으면 더 들어간다.
     한 줄을 막 넘는 길이(공백 빼고 약 39~44자)가 꼬리 줄이 된다. 쓸 때부터 몇 글자 줄여 한 줄에 맞춘다.
5. **쪽 아래 빈칸**: `HR fill report.pdf --hwpx report.hwpx`
   - 빈칸이 45 mm를 넘는 쪽을 표시한다. 장 끝·쪽 나눔 직전 쪽은 정상이다.
   - 다음 쪽 첫머리가 큰 그림이면 다음 중 하나로 고친다.
     - 그림 폭을 줄인다(`폭=`).
     - 그림을 둘로 나눠 관련 문단 뒤에 하나씩 둔다.
     - 문단 순서를 바꾼다.
   - 제목(「N) 절 제목」, □ 제목, 기관 표시 줄)이 쪽 끝에 홀로 남으면 다음 문단과 붙인다(keepWithNext).
   - 장 끝의 빈 줄 때문에 빈 쪽이 생기면 그 빈 줄을 지운다.

## 한컴 PDF 자동화(macOS) 함정

- **사용자가 입력 중이면 기다린다.** 키보드·마우스가 12초 이상 멈췄을 때만 한컴을 잠깐 앞으로 올리고, 키를 보내기 직전에 맨 앞 앱과 입력 여부를 다시 본다.
  - 옛 방식(정해진 시각에 Return)은 사용자가 메신저에 입력 중일 때 키가 그쪽으로 갔고 한컴 저장 창이 남았다.
  - 남은 「PDF로 저장하기」 창은 스크립트가 Escape로 취소한다.
- **화면이 꺼져 있거나 잠겨 있으면 못 뽑는다**(종료 코드 3). 한컴이 문서를 열어도 창 목록이 0개로 잡힌다.
  - 덮개를 닫고 외장 모니터로 쓰는 경우가 있으므로 덮개가 아니라 `Display Asleep`과 화면 잠금을 기준으로 본다.
  - 이때는 「한컴 쪽 확인 대기」로 보고하고, 화면이 켜진 뒤 다시 돌린다. 30초마다 화면 상태를 보는 대기 작업을 백그라운드로 걸어도 된다.
- 「한컴 자동 업데이트」 창이 뜨면 「취소」를 누른다.
- 「자동 저장 파일 복구」 창이 뜨면 스크립트는 멈춘다(종료 코드 4). 사용자 문서의 자동저장본일 수 있으니 사람이 「불러옴」으로 보존한다.
- 한컴을 종료(quit)하지 않는다. 작성자 문서가 열려 있을 수 있다.
- 한컴 PDF는 A4 쪽 안에 본문이 약 0.73~0.77배로 축소되어 저장된다. 쪽 나눔·줄바꿈은 실제와 같다. `page_fill.py`가 글자 폭으로 배율을 보정한다.
- 100 MB·130쪽 문서는 PDF가 생기기까지 몇 분 걸린다. 스크립트는 파일 크기가 멈출 때까지 기다린다. 대기 상한은 `HR pdf 문서.hwpx 1500`처럼 준다.

## 사용자가 한컴에서 고친 뒤

1. `python extract_spec.py 수정본.hwpx -o report.yaml --match-figs <그림 폴더>`
2. `python build_report.py report.yaml -o 재빌드.hwpx`
3. `python diff_hwpx.py 재빌드.hwpx 수정본.hwpx` → **동일**이면 spec이 수정본을 완전히 담은 것이다. 이제 spec을 고쳐 다시 빌드해도 된다.
   - 작성자가 무엇을 고쳤는지는 `HR learn 이전빌드.hwpx 수정본.hwpx -o 수정포인트.md`로 읽는다(SKILL.md 7절).
4. 차이가 남으면 spec으로 표현할 수 없는 수정이 있다는 뜻이다(글자 모양 직접 변경 등). 다시 빌드하지 말고 수정본에 패치한다.
