# 내 문체 만들기 (style: personal)

사용자가 「내 문체로」를 고르면 사용자가 직접 쓴 보고서로 `~/.hwp_report/style.md`를 만든다.
만든 뒤로는 보고서 본문을 쓸 때 이 파일을 `writing_rules.md`의 A·B(기본 문체)보다 먼저 따른다.
- C(서식)와 E(작업 방식)는 문체와 관계없이 그대로 지킨다.
- 게이트도 기본 문체 규칙 대신 이 파일 맨 위 `lint:`를 쓴다.

## 순서

1. **샘플 받기**: 사용자가 **직접 쓴** 보고서·계획서 3~10개를 받는다. 남이 고쳐 쓴 문서나 양식 안내문은 빼 달라고 한다.
   - hwpx, docx, pdf, txt, md를 받는다.
   - .hwp는 한글에서 「다른 이름으로 저장 → hwpx」로 바꿔 달라고 한다.
2. **원문·통계 뽑기**: `HR style 파일1 파일2 …` → `~/.hwp_report/style_samples/`에 원문(.txt)과 `stats.md`가 생긴다.
   - stats.md 항목: 끝맺음 비율, 글머리 기호, 줄 길이, 괄호·화살표·영문 비율, 자주 쓰는 연결 표현과 줄 끝
3. **원문을 직접 읽는다.** 통계만 보지 말고 각 파일에서 대표 문단을 골라 아래 항목을 판단한다.
4. **아래 틀대로 `~/.hwp_report/style.md`를 쓴다.**
   - 예시 문장은 반드시 샘플에서 **그대로 인용**한다. 지어내지 않는다.
   - 개인정보·과제 내부 수치는 예시에서 가린다.
5. **확인받기**: 사용자 보고서의 한 절을 이 문체로 다시 써서 보여 주고, 맞는지 묻는다. 고칠 점은 style.md에 반영한다.
6. `HR config set style personal`

## style.md 틀

```markdown
---
lint:                      # 게이트가 쓰는 정규식 (없으면 빈 목록)
  forbid: []               # 쓰면 ERROR — 예: ['협력팀', '\(그림\s*\d']
  warn: []                 # 쓰면 WARN — 예: ['무인', '하였다\.?$']
---
# ○○○ 보고서 문체

## 한 줄 요약
(예: 짧은 개조식, 명사형 종결, 영문 기술어 그대로, 괄호 최소)

## 끝맺음
- 주로: (예: 명사형 「~구축」 62%, 「~함」 20%) — 근거: stats.md
- 쓰지 않음: (예: 「~하였다」, 마침표)
- 예: 「(샘플 인용)」

## 글머리·구조
- 기호 체계: (예: ｏ → - → ‧, 들여쓰기 3단)
- 한 항목 길이: (예: 1~2줄, 80자 안팎)
- 수치 표기: (예: 「98.5 %」 띄움, 범위 「~」)

## 어휘
- 즐겨 쓰는 표현: (예: 「~를 기반으로」, 「~을 통해」)
- 피하는 표현: (예: 「무인」 → 「자동화」)
- 영문 용어: (예: 약어 그대로, 처음 한 번만 풀어 씀)

## 예시 (샘플 원문 그대로)
- 「…」
- 「…」
```

## 다른 문체를 쓰는 방법

- **기본 문체**(`style: default`): `writing_rules.md`를 따른다. 기관 보고서 표준 개조식이다.
- **설치된 문체 스킬**(`style: skill:<이름>`): 그 스킬의 SKILL.md를 문체 가이드로 따른다. 예: `skill:style-ko-report-bullet`.
- 문체만 바꾸고 양식은 그대로 두려면 `HR config set style …`만 실행한다.
