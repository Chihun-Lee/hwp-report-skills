# spec(YAML) 문법

보고서 한 편은 YAML 파일 하나로 쓴다. 이 파일이 원본(SSOT)이고, hwpx는 여기서 만든 결과물이다.
- 전체 예시: `examples/report.example.yaml`
- 실제 보고서에서 역추출한 spec: `extract_spec.py` 결과

경로는 spec 파일 위치를 기준으로 읽는다.

## 1. 공통

```yaml
form: default                       # 생략 시 설정(config)의 양식. 등록한 양식 이름·폴더·hwpx 경로도 됨
figures: [figs, ../그림/out]        # 그림 폴더(여러 개 가능). 그림 ID = 파일 이름(확장자 뺌)
caption_format: "<{}>"              # 캡션 형식. 문서 관례대로 "[{}]" 등 (writing_rules C1)
caption_mode: below                 # (게이트) below | above(그림 위 ‧ 줄) | none — 엔진은 below만 만든다
figure_box_mm: [150, 105]           # 그림 상한(폭, 높이)
figure_dpi: 400                     # 그림 설계 해상도 — 픽셀 × 7200/dpi HWPUNIT = 설계 크기 1:1
year: 1                             # (선택) 게이트: 성과 절에 다음 연차 내용이 있으면 경고
lint:                               # (선택) 게이트 설정 — 이 문서의 「문서 프로필」
  forbid: [업체명1, 업체명2]        #   금지어(ERROR)
  replace: {무인: 자동화}           #   과제 용어(WARN): 왼쪽을 쓰면 오른쪽으로 바꾸라고 알림
  abbrev_gloss: never               #   약어 풀이 괄호: never(풀이 없이, 기본) | first(첫 등장에 풀이하는 문서)
```

- `lint`는 기본 문체(`config style: default`)일 때 기본 규칙에 더해진다. 규칙 근거와 ★ 표시는 `writing_rules.md`.
- 남의 글이 섞인 문서(수합본·통합 양식)는 `HR check 문서.hwpx --form 원본양식.hwpx`로 원본에 있던 글을 빼고 검사한다.

## 2. 표지·제출문·요약표

```yaml
cover:
  title_ko: 과제명 국문            # 표지·요약표가 아니라 표지 제목과 제출문 문장에 들어감
  title_en: Project title
  date: " "                        # 표지 「2026. 11.」 자리. 비우려면 " "
  submit_date: "년      월      일"  # 제출문 날짜 + 요약표 확인란 날짜(둘 다)
participants:                      # 제출문 아래 4×3 표: "행,열": 값 (여러 줄은 리스트)
  "0,2": 홍  길  동
  "3,1": [참여연구원1  참여연구원2, 참여연구원3]
summary:                           # 요약표(39×29) 칸: "행,열": 값 — 칸 주소는 form_map.md
  "8,10": 과제명 국문
summary_sign: 홍  길  동           # 요약표 확인란 「연구책임자: ㅇ ㅇ ㅇ (인)」 자리
summary_fit_rows: [37]             # 글이 길어 행 높이를 늘릴 요약표 행(영문 키워드 등)
toc: {page_numbers: false, attachments: false}   # 목차 쪽번호·[별첨자료] 남길지
guide_box: false                   # 양식의 「작성 안내」 박스 남길지
```

## 3. 본문 — 개조식 마크업

`overview`(1장), `work`(2장), `target_notes`, `unplanned`, `next_year.N` 값은 여러 줄 문자열(`|`)로 쓴다.

| 줄 | 결과 |
|---|---|
| `## 텍스트` | **ｏ 굵은 소항목**, 다음 문단과 함께 묶음. 2장의 「(세부기술1) …」 절 제목 |
| `# 텍스트` | 굵은 제목(들여쓰기 없음) |
| `o 텍스트` | ｏ 항목 |
| `- 텍스트` | - 항목 |
| `· 텍스트` | ‧ 항목. `‧` `*` `.`로 시작해도 같음 |
| `※ 텍스트` | ※ 메모(- 항목 들여쓰기) — 다른 작성자 몫 자리표시 |
| `[그림 ID] 캡션` | 그림 + `<캡션>`. ID는 그림 폴더의 파일 이름 |
| `[그림 ID 폭=110] 캡션` | 폭 110 mm로 고정(비율 유지, 상한 무시) |
| (빈 줄) | 빈 문단. 앞 문단 모양 그대로 |
| 그 밖 | 들여쓰기 없는 본문 |

**빈 줄은 엔진이 알아서 넣는다**(사용자 확정 규칙).
- `##`·`o` 앞(블록 첫 줄 제외): 묶음 사이 빈 줄
- 그림 캡션 뒤: 빈 줄. 다음이 `##`·`o`·빈 줄·블록 끝이면 넣지 않음

그 밖에 빈 줄을 더 두고 싶으면 spec에 빈 줄을 쓴다.

```yaml
work: |
  ## (세부기술1) 시험 절차 표준화 및 기초 데이터 확보
  - 1차년도는 기준 시료군을 대상으로 함
  [그림 fig_plan] 연차별 확장 계획
  - 시료 20종의 측정 절차 설계
  · 측정 가능성이 높은 조건을 우선하여 …

  [그림 fig_result 폭=120] 시료별 측정 결과
  ## (세부기술2) …
  ※ 데이터 표준 설계 내용은 ○○○ 작성분으로 수합
```

## 4. 표

```yaml
review:                     # 2장 끝 「진도점검 지적사항 및 반영사항」: [지적, 반영] 행 목록 (앞에 ‧ 자동)
  - [지적 내용, 반영 내용 …]
progress:                   # 3-1) 진척도: 세부기술 칸(첫 열)이 병합된 묶음
  - label: [①, 기반 구축]          # 첫 열 칸(여러 줄)
    rows:
      - [계획, 실적, 80%]                       # 계획 · 실적 · 진도율
targets:                    # 3-2) 기술적 성과목표 달성도
  header: {"0,6": [연구개발, 전국내수준, (2025)], "0,7": [개발목표치, (2026)]}
  groups:
    - label: [①, 데이터]
      rows:   # 평가항목 · 단위 · 가중치 · 세계최고 기관명 · 성능수준 · 국내수준 · 목표치 · 실적
        - [데이터 구축 건수, 건, "50", "-", "-", "-", "500", [집계 중]]
target_notes: |             # 달성도 표 아래 설명(개조식)
  o …
outputs:                    # 3-3) 세부 정량성과 — 여기 적은 □ 항목만 남기고 나머지는 지움
  국내 및 국제 학술회의 발표:
    - ["1", 발표 제목, 발표자, "2026. 07.", 개최지, 국가]
  연구시설ㆍ장비:
    - [기관, 장비명, …]
  기타 성과: ["‧ 학술행사 조직", "‧ 현장실습 지도"]
outputs_note: false         # 「※ 해당되는 항목만 …」 안내문 남길지
reference_notes: true       # <참고 1·2> 표 남길지
unplanned: |                # 3-4) 계획하지 않은 성과 (빈 문자열 → 「해당없음」, 키 생략 → 양식 안내문 유지)
  o …
next_year:                  # 4장: 번호(또는 제목 앞부분) → 개조식
  1: |
    o 세부기술1: …
  3: |
    o …
```

- 값이 리스트면 칸 안 여러 줄이 된다.
- 숫자는 따옴표로 감싸 문자열로 둔다. 「"1,500"」, 「"50"」.
- 3-3)의 □ 항목 이름은 양식 제목의 앞부분만 같아도 된다.
- 5) 연구개발비 사용실적 표는 건드리지 않는다. 책임자가 기관 회계시스템 캡처로 채운다.

## 5. 다른 양식 — sections · tables

기본 양식에 없는 제목은 `sections:`(제목 정규식 → 개조식)와 `tables:`(제목 뒤 첫 표)로 채운다. 자세한 것은 `forms.md`.

```yaml
sections:
  '^□ 추진 방향': |          # 제목 아래 ~ 다음 제목·표 앞까지의 양식 글을 이 내용으로 바꿈
    o …
tables:
  - after: '^□ 추진 일정'
    rows: [[항목, 1분기, 2분기]]
    header_rows: 1
  - after: '^□ 예산'
    cells: {"1,2": "100"}
```
